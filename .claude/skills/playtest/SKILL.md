# /playtest

사람이 실제로 플레이한 결과를 `projects/<id>/playtests/<YYYY-MM-DD>.md` 에 남기고, 규칙 결함을 Q 로 연결한다. 가상 플레이는 `/simulate` 가 한다.

## 인자: $ARGUMENTS

- `<game-id>` 필수. 날짜가 없으면 오늘. 같은 날 두 번째면 `-2` 를 붙인다.

## 1단계: 수집

사용자에게 없는 정보만 묻는다:

1. 인원, 참가자 경험 수준, 소요 시간
2. 결과 (누가 어떻게 이겼는지, 어느 종료 조건이었는지)
3. 규칙 때문에 멈췄던 순간 (가장 중요)
4. 지루했거나 혼란스러웠던 구간
5. 핵심 경험(concept.md)이 나왔는지

## 2단계: 기록

- `projects/<id>/playtests/TEMPLATE.md` 형식으로 쓴다. 규칙 버전은 CLAUDE.md frontmatter 의 version.
- "진행 요약" 은 규칙 ID 를 인용한다. 어떤 규칙이 실제로 쓰였는지가 남아야 한다.
- 이슈 표의 각 줄에 관련 규칙 ID 와 심각도를 적는다. 규칙이 없어서 멈춘 경우는 규칙 ID 대신 "없음" 이라고 쓴다.

## 3단계: Q 등록

- 이슈 중 "규칙이 없거나 모호해서" 생긴 것은 open-questions.md 에 Q 로 등록한다. "관련:" 에 규칙 ID 와 플레이테스트 파일명.
- 이슈 중 "규칙은 명확한데 재미가 없어서" 생긴 것은 Q 가 아니라 이슈 표에만 남긴다. 밸런스 변경은 사용자 결정이고, 결정되면 `/add-rule` 로 반영한다.
- 이미 등록된 Q 와 같은 내용이면 그 Q 에 플레이테스트 파일명을 덧붙인다.

## 4단계: 현황판

- CLAUDE.md 의 "지금 할 일" 에 이번 플레이테스트에서 나온 우선순위 높은 이슈를 반영한다.
- `updated` 를 오늘로 한다.

## 보고

기록 파일 경로, 이슈 수, 새로 등록한 Q, 기존 Q 에 연결한 것.
