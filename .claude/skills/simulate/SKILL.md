# /simulate

`rules.md` 와 `design.md` 만 보고 게임을 진행해 본다. concept.md 와 decisions.md 는 보지 않는다. 규칙서에 없는 것은 "상식" 으로 채우지 않고 멈춘다. 그 멈춘 지점이 곧 미결 사항이다.

## 인자: $ARGUMENTS

- `<game-id>` 필수.
- 인원, 라운드 수, 시나리오는 선택. 없으면 최소 인원으로 셋업부터 2라운드.
- 시나리오 예: "전사가 첫 턴에 몬스터를 공격한다", "두 플레이어가 동시에 승리 조건을 만족한다", "덱이 비었을 때".

## 1단계: 준비

- rules.md, design.md 를 읽는다.
- 주사위와 카드 결과를 **미리 정해서 기록한다**. 시뮬레이션 중에 임의로 고르지 않는다. 예: "이동 주사위: 3,4 / 2,5 / 6,1 …".
- 시나리오가 특정 상황을 노린다면 그 상황이 나오도록 주사위 값을 고른다. 고른 이유를 적는다.

## 2단계: 진행

각 단계를 아래 형식으로 쓴다.

```
[R1 / P1 전사 / 이동 단계]
- 주사위 3+4=7, 민첩 2 → 이동력 9 (R-5.1)
- (0,-1) → (0,-2) 평지 비용 3, 남은 6 (R-5.2, R-6.1)
- ...
```

- 모든 판단에 규칙 ID 를 붙인다. 붙일 규칙이 없으면 `⚠ GAP:` 으로 표시하고 그 지점에서 가장 보수적인 해석을 골라 계속 진행한다. 고른 해석도 적는다.
- 두 규칙이 다른 결과를 내면 `⚠ CONFLICT:` 로 표시한다.
- 결과가 주사위가 아니라 "해석" 에 따라 갈리면 그것이 결정론성 결함이다.

## 3단계: 기록

- `projects/<id>/playtests/sim-<YYYY-MM-DD>-<n>.md` 로 저장한다. n 은 같은 날 몇 번째인지.
- 파일 앞에: 규칙 버전, 인원, 시나리오, 미리 정한 주사위 값.
- 파일 끝에: 발견한 GAP/CONFLICT 표 (규칙 ID, 상황, 고른 해석, 후보).

## 4단계: Q 등록

- 발견한 GAP/CONFLICT 중 open-questions.md 에 없는 것을 Q-(최대+1) 부터 등록한다. "관련:" 에 규칙 ID 와 시뮬레이션 파일명을 적는다.
- rules.md 는 고치지 않는다.

## 보고

- 진행한 라운드 수, 인용한 규칙 수, 발견한 GAP/CONFLICT 수, 새로 등록한 Q.
- 같은 시나리오를 다시 돌려도 같은 결과가 나오는지 (주사위가 같다는 전제에서). 아니면 어디서 갈리는지.

## 규칙

- 규칙서에 없는 것을 지어내서 진행하지 않는다. 멈추고 표시한다.
- 시뮬레이션은 규칙 검증이지 밸런스 판단이 아니다. "너무 강하다" 같은 의견은 관찰 란에 따로 적는다.
