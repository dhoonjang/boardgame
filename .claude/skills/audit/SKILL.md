# /audit

`projects/<id>/rules.md` 가 "어떤 상황에서든 결과가 하나로 정해지는가" 를 검사한다. 파일을 고치지 않는다. `--register` 가 있을 때만 발견한 미결을 open-questions.md 에 Q 로 추가한다.

## 인자: $ARGUMENTS

## 1단계: 기계적 검사

```bash
bash scripts/lint-rules.sh <id>
```

결과를 그대로 보고에 포함한다.

## 2단계: 의미 검사

rules.md, design.md, open-questions.md 를 전부 읽고 아래 항목을 검사한다. 각 발견은 규칙 ID 를 인용한다.

| 분류 | 검사 내용 |
|---|---|
| UNDEFINED_TERM | 용어집에 없는 명사가 규칙에 쓰였다 |
| AMBIGUOUS | lint 목록 밖의 모호한 표현. "빠르게", "근처", "충분히", 주어 없는 문장, "~하거나 ~한다" 로 두 결과가 열린 문장 |
| CONFLICT | 두 규칙이 같은 상황에 다른 결과를 낸다. 우선순위 규칙으로 해소되는지 확인 |
| GAP | 아래 체크리스트의 상황을 다루는 규칙이 없다 |
| MISMATCH | rules.md 의 수치·명칭이 design.md 표와 다르다 |
| ORDER | 동시에 발생하는 효과의 해결 순서가 없다 |
| DEAD_REF | 존재하지 않는 카드 ID, 표, 섹션을 가리킨다 |

### GAP 체크리스트

- 동점: 순서 결정, 승자 결정, 자원 배분에서 같은 값일 때
- 자원 고갈: 덱이 비었을 때, 토큰이 모자랄 때, 점수가 음수가 될 때
- 인원 경계: 최소·최대 인원에서 규칙이 성립하는가. 같은 역할 중복
- 순서: "먼저", "다음" 이 누구 기준인지. 한 턴에 같은 행동 반복 가능 여부
- 불가능한 행동: 이동할 곳이 없을 때, 대상이 없을 때, 비용을 낼 수 없을 때
- 강제 효과의 충돌: 밀치기·이동 목적지가 막혔을 때
- 비공개 정보: 무엇이 공개이고 무엇이 비공개인지, 확인 방법
- 게임 종료 순간: 여러 종료 조건이 동시에, 종료 후 남은 효과
- 무한 루프: 서로를 발동시키는 효과

## 3단계: 보고

```
| # | 분류 | 규칙 | 내용 | 제안 |
```

- 심각도 순으로 정렬: CONFLICT, GAP, ORDER 가 위.
- "제안" 은 후보 답을 적되 결정하지 않는다. 결정은 사용자가 `/add-rule` 로 한다.
- 마지막에 요약: 발견 n건, 그중 이미 Q 로 등록된 것 m건, 새로 발견된 것 k건.

## `--register` 일 때

- 새로 발견된 것만 open-questions.md 의 "열린 질문" 에 Q-(최대+1) 부터 추가한다. 형식은 템플릿을 따르고 "관련:" 에 규칙 ID 를 적는다.
- rules.md 는 건드리지 않는다. TBD 마커는 `/add-rule` 이 규칙을 만질 때 넣는다.

## 규칙

- 읽기 전용. `--register` 없이 파일을 고치지 않는다.
- 기획서에 없는 답을 "상식" 으로 채우지 않는다. 답이 없으면 GAP 이다.
